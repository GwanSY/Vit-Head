# BumbleBee ViT

代码独立放在此目录，当前只做 CPU 上的 ViT-base 实验。准确率使用替换头后的完整明文模型，时间使用实际 BumbleBee 两方安全推理。

第一阶段实验位于 `out/10/`，入口为 `study.py`；第二阶段单 Block 诊断位于 `out/11/`，入口为 `mixed.py`。主输出为 `cost.csv`、`heads.csv`、`acc.csv`、`time.csv`，对应四张 PDF；头方案保存在 `plans.json`。来源、冻结规则、逐图预测、检查记录和原始安全日志统一放在 `log/`。旧实验 `out/06–09/` 保留原始记录。

`Z = QKᵀ / 8`，每个头维度为 64。S 使用 Softmax；R 使用 `ReLU(Z) / sum(ReLU(Z))`，零行输出零；L 使用 `αZ`。
α 在 2,000 张校准图上按 `ZV` 对 `Softmax(Z)V` 拟合，允许负数，无裁剪、无权重微调。头类型及 α 在推理前固定并公开。
这里的 L 是线性权重映射；当前仍计算完整 QK 和 AV。
`heads.py` 共用 QK；joint 合并各组权重后做一次 AV，split 分组做 AV，再按原头顺序还原。这两种布局复用上游已有的安全矩阵乘法和打包实现。

数据使用同一份 ImageNet 验证集内部划分：2,000 张 calibration、5,000 张 selection、43,000 张 holdout，各部分互不重叠。
本轮新增明文计算均为 CPU FP32。复用不变的前缀和其他头输出后，仍运行变更后的 block、所有剩余 block 及分类器；每个单头变体和新组合都在首批真实图片上核对完整前向，最大误差为 0。
历史 selection 预测仅在模型及头方案相同、当前 CPU 基线逐图 Top-1 与原记录完全一致时复用，并标注来源；这些旧预测在切换为 CPU 实验之前由 A100 FP32 生成。holdout 全部重新使用 CPU 实测。

本轮实验量固定如下，不按准确率预算筛除探索候选；1 个百分点仅作为参考线。

- 成本：Z→A 和 QK→A→AV，分别测 1/12 头、S/R/L，交错顺序独立重复 5 次，共 60 次真实安全执行。
- 单头：144 个头分别替换成 R/L，共 288 个变体，各在 2,000 张 calibration 图上实际分类。
- 组合：R-only、L-only、Mixed，替换 6/12/24/48 头；每组含敏感性选择、均匀替换及 5 个随机种子，共 84 个新方案，加上历史方案及基线共 95 项。随机对照匹配敏感性方案每层的 R/L 数量。
- 独立验证：读取 selection 结果后冻结 10 个代表方案，再实际运行 43,000 张 holdout；不根据 holdout 调整方案。
- 完整安全计时：S、R48、L6、L48、M6、M48，每组新建两方运行时独立重复 3 次；历史 R12/A24 单独标注，不参与新基线的速度比较。

12 头成本如下，时间为 5 次中位数，通信为两方发送字节之和。输入是实际 ViT 第一层激活，形状为 batch=1、197 tokens、head dim=64。attention core 不含 QKV/O 投影及 FFN。

映射成本差异明确；共同的 QK/AV 仍消耗约 64.34 MiB 通信。L 映射只有公开系数乘法和安全截断，可能不调用 HE；输入依然是秘密共享，计时依然来自真实 MPC。
所有测量均核对两方 AShr 输入、通信闭合和矩阵算子数量，通过数值检查，GPU 调用数为 0。

单头实测 calibration 基线 Top-1 为 80.15%。R 单头损失范围为 −0.55～6.35 个百分点，L 为 −0.75～10.35 个百分点；这显示头之间的容忍度有差别。
热图色标聚焦 ±1 个百分点，超过 1 的实际值写在格子内。
单头损失只用来提出组合，不相加作为组合准确率。敏感性选择并非总优于均匀或匹配随机对照，当前排序不保证最优。
组合曲线的随机阴影显示 5 个种子的均值 ± 标准差；每个实际方案的逐图配对区间保存在 `acc.csv`。

CPU 每方 25 个线程，固定在物理核 0–24、48–72；两方位于同一主机隔离容器。网络每方向 1 Gbps、延时 0.25 ms。
原生库为 `build/cpu.so`，构建不启用 CUDA，源码及编译命令记录在 `build/cpu.json`。
精度为 FM64/f18、intrinsic GELU FM32/f12、Exp FM64。完整模型核对 12 次 intrinsic GELU、73 次普通及 24 次批量矩阵乘法。
上游使用 16 位 EqualAP，R 的零行保护使用非负分母 `> 0`，不能改为 `== 0`。
时间取两方原生执行的最大值，排除加载和编译；完整模型包含新运行时的协议初始化开销。微基准先预热一次。
成本测量关闭输入归属优化并检查 AShr；完整 ViT 保留原版输入优化，投影后的 Q/K/V 本身就是共享值。
`conversion_calls` 包含内部掩码、提升等步骤，不能直接当作协议边界次数。

后续诊断写入 `out/12`。`secure_cost_study.py` 固定四个新增 Block（S10R2、S8R4、S10L2、S10R1L1）及四个复测对照，每组预热一次后测五次；完整 ViT 的 E0/E1/E2/E3 各测六次独立冷执行，按轮交错。E1 在第 0、6 层放置 R12，E2 在第 0、3、6、9 层放置 S6R6，E3 全部十二层为 S10R2，后三者均为 24 个 R 头。此处只诊断成本，不按准确率预算筛选，沿用原权重、头函数、精度与数值验收。

`cost_analysis.py` 固定 P0/P1 分解，修正旧表按较慢方选取等待计时产生的角色混杂。矩阵类包含卷积嵌入；同层级 HLO 包含计算、协议内部处理及等待。单头/12 头加性模型、组数模型与协议特征模型分别评估，四个新组合留出，另按旧组合嵌套交叉验证。单头选择已有编译器会降为 slice，组织特征按实际 gather 元素量计算。`inspect_cost_ir.py` 只离线编译；SHA 与真实执行完全一致后，`group_costs.py` 才把真实 HLO 区间关联到组类型和张量形状。离线编译不是性能样本。
